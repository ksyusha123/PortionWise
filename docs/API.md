# HTTP API

Адреса локальной Compose-сборки: User `http://localhost:8081`, Analysis `http://localhost:8082`, Diary `http://localhost:8083`. Внутри сети используются `user-service`, `analysis-service`, `diary-service`.

Каждый сервис: `GET /healthz` → `{"status":"ok"}`. Это liveness-проверка, она не вызывает зависимости.

Ответ ошибки: `{"error":"описание"}`. Типичные статусы: 400 некорректный ввод, 401 нет действительного токена, 404 нет доступной записи, 409 анализ выполняется, 429 исчерпана квота, 502 ошибка ИИ, 503 недоступен зависимый сервис.

## Авторизация

Доверенный бот вызывает `POST /internal/auth/telegram` с заголовком `X-Internal-Key: <INTERNAL_KEY>` и телом:

```json
{"telegram_id":123456789,"name":"Анна"}
```

Ответ: `{"user":{"id":"...","name":"Анна","timezone":"UTC"},"token":"..."}`. Повторный вход возвращает тот же внутренний ID. Этот endpoint нельзя открывать недоверенным клиентам: Telegram ID должен происходить из проверенного канала Bot API.

Все дальнейшие запросы используют `Authorization: Bearer <token>`.

## User Service

| Метод | Путь | Описание |
|---|---|---|
| GET | `/me` | Свой профиль |
| PUT | `/me` | Полностью заменить имя, часовой пояс и норму |

```json
{"name":"Анна","timezone":"Asia/Yekaterinburg","target":{"calories":2000,"protein":120,"fat":65,"carbs":230}}
```

`target: null` удаляет норму. Предпочтителен IANA-часовой пояс, не числовое смещение: DST учитывается стандартной библиотекой Go.

## Analysis Service

| Метод | Путь | Описание |
|---|---|---|
| POST | `/analyses` | Multipart: поле `photo`; обязателен `Idempotency-Key` |
| GET | `/analyses/{id}` | Только собственный результат |
| GET | `/quota` | Локальная дата, лимит и остаток |

Фото: JPEG/PNG до 5 МБ, до 25 Мп. Статусы анализа: `pending`, `done`, `no_food`, `failed`. В квоту входят все, кроме `failed`.

```json
{"id":"...","user_id":"...","day":"2026-11-16","status":"done","food":{"name":"Рис","items":[{"name":"Рис","grams":200,"per_100g":{"calories":130,"protein":2.7,"fat":0.3,"carbs":28}}],"nutrition":{"calories":260,"protein":5.4,"fat":0.6,"carbs":56}},"remaining":4,"created_at":"2026-11-16T10:00:00Z"}
```

## Diary Service

| Метод | Путь | Описание |
|---|---|---|
| POST | `/meals` | Создать запись; `request_key` обязателен |
| GET | `/meals/{id}` | Прочитать свою запись |
| PUT | `/meals/{id}` | Заменить блюдо и время; исходный снимок остаётся |
| DELETE | `/meals/{id}` | Удалить свою запись, ответ 204 |
| GET | `/days/{YYYY-MM-DD}` | Записи, сумма, текущая норма и остаток |

Ручная запись:

```json
{"request_key":"unique-client-request","eaten_at":"2026-11-16T13:30:00+05:00","food":{"name":"Йогурт","nutrition":{"calories":120,"protein":8,"fat":4,"carbs":13}}}
```

Запись по фото дополнительно содержит `source_analysis_id`. Поле `food` содержит исправленную пользователем версию. При наличии `items` сервер вычисляет итог из `per_100g * grams / 100`, переданный `nutrition` игнорируется. Без ингредиентов используется КБЖУ порции.

Сервер сам задаёт `id`, `user_id` и `analysis_snapshot`. Для фото проверяет собственника анализа через HTTP. Snapshot содержит исходный результат, а не исправления пользователя. Повторы `request_key` или одного `source_analysis_id` возвращают ранее сохранённую запись (200 вместо 201). Один анализ можно сохранить в дневник один раз; для другой порции добавьте ручную запись.

`eaten_at` содержит RFC3339 со смещением; в БД нормализуется к UTC. День определяется по часовому поясу профиля с полуоткрытым интервалом от местной полуночи до следующей местной полуночи.

При отказе User Service запрос дня может передать `?timezone=Asia%2FYekaterinburg`; вернутся записи и сумма, `target_unavailable: true`. Если профиля нет и запасной часовой пояс не указан, вернётся 503. Если User Service доступен, профиль имеет приоритет над query-параметром.

Сервис не принимает идентификатор владельца из тела запроса как основание доступа: авторство всегда берётся из подписанного токена.
